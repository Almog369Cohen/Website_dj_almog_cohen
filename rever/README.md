# רבר הפקות · מערכת ניהול

מערכת ניהול לידים ואירועים: **היום** (פולואפים + יומן), **לידים**, **כרטיס ליד** עם שליחת וואטסאפ מתבניות, **יומן**, **כספים**, **תבניות הודעה**, **הגדרות**.

## הרצה מקומית
```bash
cd rever
npm install
npm run dev        # http://localhost:3100
```
בלי משתני סביבה המערכת רצה ב**מצב דמו**: נתוני דוגמה נשמרים בדפדפן בלבד.

## שלושה מצבי עבודה
| מצב | איפה הנתונים | מתי |
|---|---|---|
| דמו | בדפדפן של המכשיר | בלי שום הגדרה |
| **גוגל שיטס** | בגיליון של רבר (Apps Script) | `apps-script/HOW-TO.md`. בבנייה: `SHEETS_URL=<…/exec> scripts/build-demo.sh`, או פעם אחת במכשיר: `?connect=<…/exec>` |
| Supabase | Postgres + שרת Next | משתני Supabase (ראו למטה) |

## כניסה והרשאות
מערכת עצמאית של רבר (לא קשורה ל-Claude). הכניסה בשני שלבים:
1. **המכשיר מתחבר לחשבון הגוגל של רבר** (פעם אחת). רק חשבונות שמופיעים ב-`ALLOWED_GOOGLE_EMAILS`.
2. **כל עובד בוחר את עצמו ומקיש קוד אישי** (4-8 ספרות). כפתור "החלפה ⇄" מחליף עובד באותו מכשיר.

| מי | הרשאה |
|---|---|
| גל, ליאל | **מאסטר**: הכל, כולל כספים, הגדרות, ניהול עובדים וקודים |
| ארד (תפעול, חזרה ללקוחות) | עובד: לידים, יומן, הודעות. + מה שהמאסטרים מדליקים |
| ספיר (מזכירה) | עובד: לידים, יומן, הודעות. + מה שהמאסטרים מדליקים |

הרשאות שאפשר להדליק לכל עובד (הגדרות ← צוות והרשאות): **מחירים**, **כספים**, **מחיקה**, **עריכת תבניות**, **קישור ללקוח**.

**איך זה מאובטח:**
- כל הנתונים עוברים דרך השרת של המערכת (`/api/data`), שבודק את העובד המחובר ומסנן.
  עובד בלי הרשאת מחירים **לא מקבל את המחירים בכלל**: לא בלידים, לא בהיסטוריה, לא בתבניות. זה לא רק הסתרה במסך.
- הדפדפן לא ניגש למסד הנתונים ישירות (RLS נעול לגמרי).
- הקודים נשמרים מוצפנים (scrypt). אחרי 5 ניסיונות שגויים העובד ננעל ל-10 דקות.
- הסשן נשמר בעוגייה חתומה ל-12 שעות. שינוי הרשאה או השבתת עובד נכנסים לתוקף מיד.
- בדיקות: `npm test` (76 בדיקות: הרשאות, דף הלקוח, והשוואה בין השרת לגוגל שיטס).

במצב דמו הקודים הם: גל 1111 · ליאל 2222 · ארד 3333 · ספיר 4444.

## דף הלקוח (הזוג)
- **כתובת אחת לכל הלקוחות:** `/e`. הזוג נכנס עם הטלפון שבליד + קוד בן 6 ספרות (נוצר בכרטיס האירוע ← "קישור ללקוח").
- **רואה:** סטטוס הכנה, לו״ז (בלי "מי אחראי"), התשלומים שלו (בלי עלויות/רווח), ספקים שסומנו, פרטי האירוע, איש קשר.
- **עורך רק:** "המשימות שלנו" (רשימת המשימות של הזוג). זו פעולת הכתיבה היחידה של לקוח, והשרת בודק כל שדה.
- **אבטחה:** אסימון חתום ל-90 יום, נפרד מאסימון עובד. "קוד חדש" מנתק מיד. 5 טעויות = נעילה ל-15 דקות (גם בבקשות במקביל). תצוגה מקדימה רק לעובד מחובר.
- הקוד: `src/lib/portal.ts` (מה הלקוח מקבל), `src/lib/tasks.ts` (משימות + ולידציה), `src/app/e/` (הדף), ובגיליון `apps-script/Code.gs` (אותה לוגיקה).

## חיבור Supabase (נתונים אמיתיים)
1. ליצור פרויקט Supabase ולהריץ את `supabase/migrations/001_init.sql` ב-SQL Editor.
2. Authentication → Providers → **Google**: להפעיל ולהדביק Client ID / Secret מ-Google Cloud Console
   (OAuth Client מסוג Web, Redirect URI: `https://<project>.supabase.co/auth/v1/callback`).
3. Authentication → URL Configuration: להוסיף את כתובת האתר.
4. למלא את המשתנים לפי `.env.example`.
5. להיכנס עם חשבון הגוגל של רבר → "הגדרה ראשונה" → יוצרים את גל כמאסטר עם קוד → מוסיפים את ליאל, ארד וספיר.

## וואטסאפ
- **ברירת מחדל:** נפתח וואטסאפ עם ההודעה מוכנה (wa.me). עובד מיד, בלי חיבור.
  תזמון במצב הזה = ההודעה נשמרת ומופיעה בפולואפים בזמן שנקבע, ונשלחת בלחיצה.
- **אוטומטי דרך Make:** בהגדרות לבחור "שליחה דרך Make" ולהדביק כתובת Webhook.
  המערכת שולחת `POST` עם `{type, phone, name, message, send_at, lead_id}` ו-Make מעביר ל-WhatsApp API / ManyChat.

## קליטת לידים מ-Make / Meta Lead Ads
`POST /api/leads` עם header `x-webhook-secret` ו-JSON:
`{ name, phone, email?, event_type?, event_date?, guests?, venue?, source?, notes? }`.
דורש `SUPABASE_SERVICE_ROLE_KEY` ו-`LEADS_WEBHOOK_SECRET`. טלפון שכבר קיים לא יוצר כפילות, רק מקפיץ פולואפ.
